# v0.2.0 요구사항과 설계

## 범위

같은 기기의 같은 브라우저·origin에서 이어서 쓰는 참고용 냉방비 MVP. 계정, 서버, 기기 간 동기화, 실제 청구요금 계산, 외부 배포, 토스 심사는 포함하지 않는다. 기존 v0.1 요구사항은 [원문](archive/requirements-v0.1.md)으로 보존하며, 이번 버전의 동작은 이 문서를 기준으로 한다.

## 날짜와 기록

- 모든 날짜는 `Asia/Seoul` 기준 `YYYY-MM-DD`이다. 월별 합산 키는 `YYYY-MM`이다.
- 첫 설정 시 이번 달 1일부터 어제까지를 자동 추정한다. 매번 접속·포커스 복귀·한국 시간 자정에 마지막 처리일 다음 날부터 어제까지 보완한다. 백그라운드 타이머 지연에 대비해 30초 간격 및 사용자 동작에서도 날짜를 확인한다.
- 미기록 날짜는 당시 적용 중이던 평균 사용시간, **냉방 모드**, **중립 날씨계수 1**로 계산한다. 미저장 슬라이더 입력은 직접 기록으로 간주하지 않는다.
- 하루에 한 건만 저장한다. 오늘 재저장 시 교체하며, 0시간도 유효한 기록이다. 취소하면 오늘 기록을 제거하고 미저장 미리보기로 돌아간다. 취소 후 다음 날까지 미저장이면 자동 추정된다.
- 설정 변경 전 빈 과거 날짜를 이전 설정으로 채운다. 기존 기록의 설정·날씨·금액은 바꾸지 않는다. 변경 설정은 오늘 미저장 계산과 이후 날짜에 적용한다. 오늘 입력시간·모드는 설정 변경 전 입력을 유지하며 직접 조절할 수 있다.
- 날짜가 기록보다 과거로 돌아가면 변경을 중지한다. 기기 시간을 고친 뒤 다시 불러오기 한다. 자정 직후 낡은 화면에서 저장하려 하면 오늘 입력을 다시 확인하도록 막는다.

## 계산 모델

`원 = round(기준 kW × 시간 × 모드계수 × (0.86 + 평수 × 0.018) × 습도계수 × 기온계수 × 260)`

| 항목 | 값 |
|---|---|
| 기준 소비전력(kW) | 벽걸이·미상 0.65, 스탠드 1.8, 창문형 0.75, 이동식 0.9 |
| 모드계수 | 냉방 1, 제습 0.72, 취침 0.58 |
| 습도계수 | 75% 이상 1.08, 55% 이하 0.96, 그 외 1 |
| 기온계수 | 33°C 이상 1.12, 30°C 이상 1.04, 그 외 0.98 |
| 자동 추정 날씨 | 습도계수·기온계수 모두 1 |
| 입력 범위 | 방 1~60평·소수점 한 자리, 시간 0~12시간·0.5시간 단위 |

원본의 가정 기반 산식을 유지했다. 기종별 실측 성능이나 공인 요율이 아니다. 제습·취침 절감 효과를 보장하지 않는다. 누진제, 다른 가전, 기본요금, 부가세 등을 계산하지 않는다. 기록마다 원 단위로 반올림한 후 합산하여 목록 금액과 합계가 일치한다.

현재 월 누적 = 직접 입력 합계 + 자동 추정 합계 + 오늘 미저장 예상액(오늘 저장 시 0). 오늘 저장 후 입력·날씨가 바뀌어도 누적에는 저장 당시 금액을 유지한다. 하루 평균 = 누적 / 이번 달 경과 일수(오늘 포함). 월말 예상 = 평균 × 이번 달 전체 일수. 지난달 목록은 저장된 기록 합계만 표시한다.

## 저장과 복구

`localStorage['cooling-cost-preview:v1']`에 `version`, `settings`, `records`, `draft`, `firstDate`, `lastProcessedDate`를 저장한다. 기록은 날짜, 직접/추정 구분, 시간, 모드, 원 단위 금액, 당시 설정, 당시 날씨(자동 추정은 null), 산식 버전으로 구성한다.

- 읽을 때 스키마, 날짜 연속성, 입력 범위, 기록 금액과 산식의 일치를 검증한다. 지원하지 않는 버전도 손상과 동일하게 보존한다.
- 저장 완료 후에만 앱 상태와 성공 안내를 갱신한다. 저장 실패 시 변경되지 않은 마지막 저장본을 남기고 복구 화면을 표시한다.
- 저장 직전에 읽은 원문과 현재 저장소 원문을 비교한다. 다른 탭의 변경을 발견하면 덮어쓰지 않고 재조회하도록 안내한다. 저장소 이벤트도 감시한다. 브라우저 저장소에는 다중 프로세스 트랜잭션이 없으므로 한 탭 사용을 권장한다.
- 손상 데이터를 자동 초기화하지 않는다. 원본 JSON 내보내기, 다시 불러오기, 사용자가 체크한 뒤 별도 키에 원문 백업 후 초기화를 제공한다. 백업 실패 시 원본 삭제를 수행하지 않는다.
- 설정·오늘 입력·기록은 같은 origin에만 남는다. 시크릿 모드 종료, 브라우저 데이터 삭제, 주소·브라우저 변경 시 유지되지 않을 수 있다. 복구용 백업도 브라우저 삭제에는 보호되지 않으므로 중요한 원문은 파일로 내보낸다.

## 날씨

[Open-Meteo Forecast API](https://open-meteo.com/en/docs)의 `current` 기온·상대습도·날씨코드와 `Asia/Seoul` 시간대를 사용한다. 17개 시도 대표 좌표를 사용하며 위치 권한을 요구하지 않는다. 응답 범위·조회시각을 검증하고 8초 제한 시간을 둔다. 지역 변경·언마운트 시 요청을 취소하고 이전 요청 결과를 반영하지 않는다. 날짜 변경 및 30분 간격 재조회와 수동 재시도를 제공한다.

실패하면 같은 지역의 24시간 이내 최근 성공값, 없으면 지역별 예시값을 쓴다. 값의 출처와 조회시각을 화면에 표시하며, 조회 중에도 표시된 예시/최근값으로 계산할 수 있다. 직접 기록에는 사용한 출처를 함께 고정한다. 자동 추정에 과거 실제 날씨를 사용했다고 표시하지 않는다. 날씨 캐시 저장 실패는 기록 저장과 별개이며, 현재 조회 성공값은 화면에서 사용할 수 있다.

| `model.ts`, `regions.ts` | 타입, 입력 범위, 산식, 지역 좌표 |
| `dates.ts`, `ledger.ts` | 한국 날짜, 날짜별 기록 전이, 월별 합산 |
| `storage.ts` | 저장 스키마 검사, 쓰기 충돌 감지, 복구 백업 |
| `weather.ts` | API 요청, 응답 검사, 지역별 캐시 |
| `hooks.ts` | React와 저장·날짜·날씨 연결 |
| `App.tsx` | 설정, 오늘 미리보기, 월별 기록, 복구 화면 |
| `main.tsx` | 웹 진입점; `--mode toss`에서만 전용 Provider 로드 |

앱 서버나 API 키는 없다. 브라우저에서 Open-Meteo로 직접 통신한다.
